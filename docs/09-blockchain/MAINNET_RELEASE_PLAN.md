# Mainnet release plan

**Status:** Draft | **Version:** 0.1 | **Last updated:** 2026-11-14  
**Responsible role:** Smart-contract / security lead

## Purpose

Set a separate real-funds gate.

## Assumptions and dependencies

This is a documentation proposal, not an implemented or approved product. The master specification and owner approval govern scope. MVP means the proposed testnet release; later features require separate acceptance. Terms and shared states follow the [product requirements](../00-product/PRODUCT_REQUIREMENTS.md).

## Not authorised

No mainnet deployment, real assets, public savings offer or production credentials are approved. Testnet acceptance is necessary but does not establish legal suitability or financial safety.

## Release evidence

Owner-approved entity/countries/age/identity policy; jurisdiction-specific counsel opinion and licences/permissions as applicable; exact supported asset verified with issuer; final user terms/risk/custody disclosures; independent contract review of the exact build and remediation; application security results; operator/upgrader/emergency authority review; production secrets and signer ceremony; restore/incident drills; monitoring and reconciliation; real support contacts; reviewed limits, fees and liquidity plan.

## Acceptance / rollback limits

Stage rollout under explicitly approved caps; verify deployed code and initial state before accepting user funds. Production changes require named owner acceptance and immutable evidence. Do not claim an audit from internal tests. Frontend rollback does not reverse blockchain transfers; contract migration/upgrade needs a separate reviewed plan. If safe withdrawal continuity cannot be demonstrated, launch remains blocked.

See the linked decision register; recommendations are not approvals.

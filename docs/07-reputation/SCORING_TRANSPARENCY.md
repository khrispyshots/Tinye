# Scoring transparency

**Status:** Draft | **Version:** 0.1 | **Last updated:** 2026-11-14  
**Responsible role:** Product / finance / engineering leads

## Purpose

Make behavioural information inspectable and contestable.

## Assumptions and dependencies

This is a documentation proposal, not an implemented or approved product. The master specification and owner approval govern scope. MVP means the proposed testnet release; later features require separate acceptance. Terms and shared states follow the [product requirements](../00-product/PRODUCT_REQUIREMENTS.md).

## Display contract

Describe what is measured, timeframe, excluded events, correction process and data freshness. Confirmed contributions count once; pending/failed operations do not. A completed-goal count depends on the explicit metadata completion action plus verified progress context; it is not proof of repayment capacity.

MVP copy: This is a summary of your Tinye saving activity. It is not a credit score and does not guarantee financial products. Users see the underlying month/activity list and can report a missing or incorrect transaction.

## Acceptance

Changes to data trigger recalculation with versioned snapshots, evidence and an explanation. A future numeric score must publish the exact approved formula and factor contributions; model secrecy cannot justify a misleading credit claim. Support records disputes without overwriting financial truth. Do not expose profile measures to groups or partners by default.

# Features and limitations

**Status:** Draft | **Version:** 0.1 | **Last updated:** 2026-11-14  
**Responsible role:** Product owner / finance / demo lead

## Purpose

Provide a truthful capability register.

## Assumptions and dependencies

This is a documentation proposal, not an implemented or approved product. The master specification and owner approval govern scope. MVP means the proposed testnet release; later features require separate acceptance. Terms and shared states follow the [product requirements](../00-product/PRODUCT_REQUIREMENTS.md).

## Status table

| Capability | Current status | Future gate |
|---|---|---|
| Master-derived docs/design/API/contract proposals | Drafted, unapproved | Owner review |
| Running UI/auth/goals/wallet | Not implemented | Scope/stack/auth approval |
| Contract/financial flows/indexer | Not implemented, not deployed | Custody/asset/rules/security and explicit testnet authorisation |
| Rewards/history/admin/notices | Specified only | Verified source and accepted implementation |
| Yield/groups/fiat/real redemption/underwriting | Deferred or unavailable | Separate legal/product/technical approvals |
| Security audit/legal compliance | Not established | Real review of actual product/build and jurisdictions |
| Production/mainnet | Prohibited pending separate gates | Explicit owner launch consent and evidence |

## Acceptance

Update status only with build/test/receipt/reviewer references. A static page or mock API is not a working financial feature. Recorded demos must identify environment/date/limitations. No customer count, saved amount, earnings, wallet address or deployed contract is invented. Testnet assets are not represented as monetary savings.

## Purpose

Prepare an honest project summary for a future submission.

## Assumptions and dependencies

This is a documentation proposal, not an implemented or approved product. The master specification and owner approval govern scope. MVP means the proposed testnet release; later features require separate acceptance. Terms and shared states follow the [product requirements](../00-product/PRODUCT_REQUIREMENTS.md).

## Narrative

Tinye is a proposed goal-based savings and financial wellness experience: **Put something aside. Build something bigger.** It helps users set a purpose, contribute consistently, inspect verified progress and understand access to their funds. Design follows restrained, mobile-first premium fintech clarity.

Proposed NEAR use is user-approved native-network transactions and a reviewed per-owner goal vault, with off-chain private metadata, read models, noncash points and support. This architecture is not yet approved or implemented.

## Current evidence and limitations

Only planning documentation exists. There is no running app, contract deployment, verified deposit, wallet integration, audit, live yield, merchant fulfilment or customer activity. The intended next deliverable after approval is a labelled testnet prototype with real receipt verification, not a live savings offer.

## Acceptance

Any submission must match actual implemented evidence at that time and disclose custody/upgrade assumptions. No hackathon/event requirements, dates or eligibility are assumed. Update this overview after each accepted phase; do not claim documentation diagrams are operational integrations.

# Demo script

**Status:** Draft | **Version:** 0.1 | **Last updated:** 2026-11-14  
**Responsible role:** Product owner / finance / demo lead

## Purpose

Separate a documentation walkthrough from a future testnet demonstration.

## Assumptions and dependencies

This is a documentation proposal, not an implemented or approved product. The master specification and owner approval govern scope. MVP means the proposed testnet release; later features require separate acceptance. Terms and shared states follow the [product requirements](../00-product/PRODUCT_REQUIREMENTS.md).

## Available now: documentation walkthrough

1. State that Tinye is in planning; show the repository discovery and decision register.
2. Explain the saver problem and proposed mobile journey using written screen specifications.
3. Show the conditional architecture, ownership invariant and submitted/pending/confirmed distinction.
4. Show test plans, legal gates and implementation roadmap. State clearly that no app/contract/transactions exist.

## Future script after approval and testnet acceptance

Show persistent testnet label and selected asset identity → authenticate/consent/connect → create a goal → enter/review contribution → user approves in wallet → show pending, then actual verified receipt and progress → show one eligible points entry → review/sign withdrawal → verify settled payout and reconciliation → show a rejection/unknown recovery path safely → end with limitations.

Use only real testnet evidence for working claims. Synthetic educational examples must be in a separate labelled segment and never imply withdrawable earnings. No real funds or invented hashes/accounts. If network/provider fails during presentation, show truthful unknown status or recorded evidence clearly labelled with date/build; never simulate success in the live flow.

See the linked decision register; recommendations are not approvals.
